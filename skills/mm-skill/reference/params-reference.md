# mm params reference

> Reference manual for the [mm - 3D matmul visualizer](https://bhosmer.github.io/mm/ref.html).
> Upstream: [online tool](https://bhosmer.github.io/mm) · [full reference](https://bhosmer.github.io/mm/ref.html) · [source](https://github.com/bhosmer/mm) · [intro article](https://bhosmer.github.io/mm/intro/)
> Chinese translation: [`params-reference.zh.md`](params-reference.zh.md)
>
> mm renders a matmul as a 3D cube: left arg / right arg / result on three faces, with rotation, zoom, value magnification, algorithm animations and blocking. Its only input is the **params JSON** (via URL `?params=`, or postMessage for live updates).

---

## 0. Quick examples

> The JSONs below are **setParams payloads** (deep merge, partials OK - the recommended way).

Minimal - default 32×32 matmul:

```json
{ "expr": "L @ R" }
```

Two-level attention (all 32×32, no external data, offline-safe):

```json
{
  "expr": "out = (attn = Q @ K) @ V",
  "sync_expr": true,
  "anim": { "alg": "vmprod", "fuse": "sync", "speed": 16 },
  "left": { "epilog": "softmax(tril(x/sqrt(k)))" }
}
```
(`left.epilog` is the attn layer's epilog; the top-level `epilog` applies to `out`.)

Specifying leaf shapes (address leaves by tree path):

```json
{
  "expr": "out = (attn = Q @ K) @ V",
  "sync_expr": true,
  "left": {
    "left": { "h": 32, "w": 16 },
    "right": { "h": 16, "w": 32 }
  }
}
```
(attn.left = Q, attn.right = K; shapes must satisfy K.h == Q.w and V.h == K.w.)

Full attention with projections (node paths match the official attngpt2 example; all leaves default 32×32):

```json
{
  "expr": "out = ((attn = (Q = input @ wQ) @ (K_t = wK_t @ input_t)) @ (V = input @ wV)) @ wO",
  "sync_expr": true,
  "anim": { "alg": "vmprod", "fuse": "sync" },
  "left": { "left": { "epilog": "softmax(tril(x/sqrt(k)))" } }
}
```

Key points:
- Only `expr` defines structure; other fields fall back to defaults. When changing `expr`, pass `sync_expr: true` so mm preserves existing settings by name.
- Expression grammar: `left @ right`, optional `result = `, parens for right-associative grouping/assignments. Names are arbitrary (`Q`, `wQ`, `input_t`, ...).
- Leaves are auto-created with defaults (32×32, row/col-major gradients) for every name in the expr - no need to declare them one by one.
- **Important**: partial updates must go through `setParams` (deep merge); URL `?params=` replaces top-level keys wholesale and partial trees will break it (see next section).

## 1. Embedding & URL mechanics

mm is a pure static frontend app. Two runtime sources:

| mode | URL | note |
| --- | --- | --- |
| online (default) | `https://bhosmer.github.io/mm/index.html` | needs GitHub Pages access |
| offline (vendored) | `/mm/index.html` | served by this skill's `serve.py` |

Embed mm in an `<iframe>`. **Two ways to apply params, with different merge semantics (key difference!)**

| mechanism | merge semantics | use |
| --- | --- | --- |
| postMessage `setParams` | **deep recursive merge**, partials OK | recommended; what templates do |
| URL `?params=<json>` | **top-level keys replace defaults wholesale** (`left`, `anim`, ... are replaced as whole objects) | only safe with complete param trees (e.g. the official attngpt2 example) |

- Partial objects via URL (e.g. `left: {h:32}`) break the params tree and throw (`Cannot read properties of undefined`); use `setParams` instead.
- The URL `expr` is a derived field regenerated by `genExpr` from the tree at init; only `setParams` + `sync_expr: true` makes `expr` drive a tree rebuild.
- `?config=<url>` loads a complete params JSON from a URL (very large configs; cross-origin needs CORS). The URL must be **absolute**: the source parses it with `new URL(config)` (no base), so relative paths throw `Invalid URL` and are silently ignored, falling back to defaults (console log only).
- After user interaction mm writes state to its own URL (internal compressed form like `?0=...&1=...` for larger params) and posts `{ search_params }` to the parent page.

**postMessage API**

| direction | message | response |
| --- | --- | --- |
| parent→mm | `{ getUrlInfo: undefined }` | `{ url_info: { json, url, compressed, search_params } }` |
| parent→mm | `{ getParams: undefined }` | `{ params }` (full current params) |
| parent→mm | `{ setParams: { props, reset } }` | none (applied immediately) |
| mm→parent | `{ search_params }` | emitted when mm's URL changes |

- `props` is a **partial params** object, recursively merged.
  Example: `{ setParams: { props: { anim: { alg: 'vvprod' } } } }`
- `reset: true` resets to mm's built-in defaults first; to reset to *your* initial state, send your full initial params back.
- To change structure (expression): `{ setParams: { props: { expr: 'X = A @ B @ C', sync_expr: true } } }`.
- Send with targetOrigin `'*'`; mm does not verify origin and replies from its own origin.
- **Limitation**: `pause` / `step` are GUI-only (menu or spacebar); not settable via postMessage.

## 2. Top level

| field | default | notes |
| --- | --- | --- |
| `expr` | `"L @ R"` | expression defining the whole visualization structure |
| `name` | `"L @ R"` | result matrix name, synced with expr |
| `epilog` | `"none"` | post-processing applied to the top-level result |

`epilog` values: `none`, `relu`, `gelu`, `sigmoid`, `silu`, `tanh`, `layernorm` (matrix-wide normalization), `softmax` (by row), `softmax(x/sqrt(k))` (SDPA scaling), `softmax(tril(x/sqrt(k)))` (causal attention).

## 3. left / right: matrix leaf nodes

Fields when the argument is a plain matrix (`matmul: false`, the default):

| field | default | notes |
| --- | --- | --- |
| `name` | `"L"` / `"R"` | name, synced with expr |
| `matmul` | `false` | whether this arg is itself a matmul |
| `h` `w` | `32` `32` | height/width; the shared k dim is auto-synced |
| `init` | `"row major"` left / `"col major"` right | initializer (see below) |
| `url` | `""` | CSV URL when `init` is `"url"` |
| `expr` | — | JS expression when `init` is `"expr"` |
| `min` `max` | `-1` `1` | value range (applies to some inits) |
| `dropout` | `0` | sparsity 0..1 for row/col & random inits |

All `init` values:

| init | effect |
| --- | --- |
| `rows` / `cols` | constant per row/col, spread over min..max |
| `row major` / `col major` | evenly spread in row/col-major order from min to max |
| `pt linear` | PyTorch-Linear-style uniform distribution |
| `uniform` / `gaussian` | uniform / gaussian random over min..max |
| `tril mask` / `triu mask` | lower/upper triangular ones |
| `eye` | identity matrix |
| `diff` | diagonal 1, subdiagonal -1 (difference operator) |
| `url` | load CSV from `url`; consumes row by row, rolls over both ways if shape exceeds data |
| `expr` | JS expression evaluated per element with variables `i, j, h, w` (index and shape) |

CSV note: cross-origin CSVs must be CORS-enabled (`raw.githubusercontent.com` works); local files go in the viz dir and are loaded same-origin as `/viz/xx.csv`.

## 4. left / right: matmul nodes

When `matmul: true`, the node becomes a "sub-cube" with fields:

- `name`: name of the subexpression's result
- `left` / `right`: recursive operands (leaves or subexpressions)
- `epilog`: per-subexpression epilog (same epilog table as above)
- `anim`: animation for this subexpression (`alg: "inherit"` default inherits from parent)
- `block`: blocking for this subexpression (normally global)
- `layout`: layout of this sub-cube (exposed on children only when `scheme: "custom"`)

Subexpressions can nest to arbitrary depth; animation proceeds leaf-to-root in dependency order, with independent subexpressions running in parallel.

---

## 5. anim: animation

| field | default | notes |
| --- | --- | --- |
| `alg` | `"none"` | algorithm (see below) |
| `speed` | `20` | 1..100 (one step per frame, regardless of algorithm) |
| `fuse` | `"none"` | fusion of adjacent matmuls: `none` / `sync` / `async` |
| `spin` | `0` | +1 counterclockwise, -1 clockwise, 0 stop |
| `hide inputs` | `false` | hide input faces during animation to inspect interior results |

`alg` values: `none`, `dotprod (row major)`, `dotprod (col major)`, `axpy`, `vmprod`, `mvprod`, `vvprod`; child nodes additionally accept `inherit`.
- `dotprod`: pairwise dot products, element by element
- `axpy`: depthwise vector-scalar accumulation over k
- `vmprod`: vector-matrix products over rows of the left arg
- `mvprod`: matrix-vector products over columns of the right arg
- `vvprod`: depthwise outer-product accumulation over k

Fusion `fuse`: adjacent planar algorithms fuse when they generate parallel planes (e.g. `A @ B @ C` all `vmprod` along i, or child `mvprod` / parent `vvprod` along k). `sync` fuses only participants that start simultaneously; `async` allows offset starts; usually identical.

---

## 6. block: blocking

| field | default | axis |
| --- | --- | --- |
| `i blocks` | `1` | rows of the root; propagates along contiguous left-argument chains |
| `k blocks` | `1` | reduction dim; parent k becomes the left child's j and the right child's i |
| `j blocks` | `1` | cols of the root; propagates along contiguous right-argument chains |

- Partitions are global (planes cut across subexpressions), representing parallelization of the whole expression; animations parallelize within blocks.
- Blocks are equal-sized, with a short final block if not divisible.
- Typical semantics: `i blocks` ≈ data parallelism (batch split), `j blocks` ≈ tensor parallelism (hidden-dim split).

---

## 7. layout: layout

Spacing (defaults are usually fine; tune for deep saturated expressions):

| field | default | notes |
| --- | --- | --- |
| `gap` | `4` | gap along shared edges between constituents (unit ≈ one row/column) |
| `scatter` | `0` | fixed offset of child **matmuls** from parents (leaf matrices unaffected) |
| `molecule` | `1` | size threshold (matmul count) at which scatter starts applying |
| `blast` | `0` | exponential scaling of scatter by subexpression size; positive scatters larger subexpressions farther, negative the opposite |

Orientation:

| field | default | notes |
| --- | --- | --- |
| `scheme` | `"blocks"` | rule for generating child-cube layouts |
| `polarity` | `"negative"` | `positive`/`negative`: argument normals toward increase/decrease of result values |
| `left placement` | `"left"` | left arg on left/right face |
| `right placement` | `"top"` | right arg on top/bottom face |
| `result placement` | `"front"` | result on front/back face |

`scheme` values:
- `blocks` (default): alternates convex/concave unfolding; usually readable and collision-robust
- `zigzag`: alternation without convexity flips; simpler flow, more occlusion
- `wheel`: 90° rotation per level; circular views for linear chains, collision-prone (fix with spacing)
- `custom`: no generative rule; layout params become exposed on every child

## 8. deco: decorations

| field | default | notes |
| --- | --- | --- |
| `legends` | `6` | name/shape legend size; 0 removes |
| `shape` | `true` | show shape legends along matrix edges |
| `spotlight` | `2` | size of the value-reveal spotlight during magnification |
| `lens size` | `0.5` | magnification lens size |
| `magnification` | `7` | magnification factor (ctrl+drag / long-press) |
| `row guides` | `0.6` | row guide brightness 0..1 |
| `flow guides` | `0.5` | flow arrow brightness/size 0..1 |
| `interior spotlight` | `false` | reveal interior intermediate values during magnification |
| `axes` | `false` | show coordinate axes |

---

## 9. viz: colors and sizes

| field | default | notes |
| --- | --- | --- |
| `sensitivity` | `"global"` | normalization range for value → size/brightness/hue |
| `min size` / `min light` / `max light` | `0.2` / `0.4` / `0.7` | min render size / lightness range (HSL; lightness→1 approaches white) |
| `elem scale` | `1.25` | global element scale factor |
| `zero hue` | `0.77` | hue at zero; positives higher, negatives lower |
| `hue gap` | `0.74` | gap from zero hue before value hues start |
| `hue spread` | `0.04` | hue change rate by magnitude |

`sensitivity` values: `global` (single range), `local` (per-matrix normalization), `semilocal` (geomean of global and local), `superlocal` (local with the matrix's minimum absolute value as the lower bound).
Values with strong variance across matrices → prefer `local`; add `deco`/`viz` tweaks for readability.

  "expr": "L @ R", "name": "L @ R", "epilog": "none",
  "left":  { "name": "L", "matmul": false, "h": 32, "w": 32, "init": "row major", "min": -1, "max": 1, "dropout": 0 },

## 13. Recipes

- **MLP chain**: `expr: "out = (x1 = (x0 = batch @ w0) @ w1) @ w2"`, anim `vmprod` + `fuse: "sync"` to show the data-parallel planes.
- **Low-rank factorization**: `expr: "out = (x0 = batch @ (w0 = w0_L @ w0_R)) @ ..."`.
- **QKV projection shapes**: wide→narrow `left {h:32,w:48}, right {h:48,w:12}`; narrow→wide `left {h:32,w:12}, right {h:12,w:48}`.
- **Causal attention**: set `epilog: "softmax(tril(x/sqrt(k)))"` on the `attn` layer.
- **Show blocking parallelism**: `block: {"i blocks": 4}` + `anim.alg: "vmprod"` (i-split ≈ data parallel); `j blocks` for tensor parallel.
- **Geometry only**: `deco: {legends:0, shape:false, "row guides":0, "flow guides":0}`, `viz.sensitivity: "local"`.
- **Align with official example data**: use `https://raw.githubusercontent.com/bhosmer/testdata/main/weights/gpt2/...csv` as `init: "url"` sources (CORS-enabled).

## 14. Notes & gotchas

- **Merge semantics (most important)**: `setParams` deep-merges (partials OK); URL `?params=` replaces top-level keys wholesale and needs complete trees or it throws. `expr` drives a rebuild only via `setParams` + `sync_expr: true`.
- **Pause/step**: not controllable via postMessage (GUI/spacebar only).
- **URL length**: very long params (several KB) get truncated in Safari's address bar; share via the **diag** menu URL or use `?config=<absolute-url>` (see section 1: must be absolute). mm auto-switches to its compressed internal format when params get large.
- **CSV cross-origin**: `init: "url"` sources must be CORS-enabled; local files go in the viz dir and are served same-origin.
- **Dimension performance**: 32-128 per side is smooth; 256/768-level (e.g. GPT-2 single-head examples) render but are heavy and slow animations down.
- **Collisions**: deeply nested expressions can overlap; tune `layout.gap/scatter/molecule/blast` or switch `scheme`. The default `blocks` scheme normally avoids collisions up to 3 generations deep.
- **`sync_expr` is a one-shot directive** on `setParams`/expr edits; it is not persisted into params.
- **Screenshots**: use browser screenshots; there is no built-in export. `cam` enables reproducible fixed viewpoints.
