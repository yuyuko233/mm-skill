## 初始状态

默认可视化
（无已保存的 URL 参数）展示两个 32x32 矩阵的一个矩阵乘 `L @ R`：
* 左操作数 `L` 以*行主序*初始化，等距分布的值从左上角的 `-1`（红）到右下角的 `1`（蓝）。
* 右操作数 `R` 以*列主序*初始化，取值范围相同。
* 结果矩阵（标注为 `L @ R`）包含矩阵乘的结果。
* 引导线平行于矩阵行，`(0, 0)` 角上有一个三角形。
* 立方体内部的引导箭头指向结果矩阵。
***R***ed（红色）扇面指向***R***ight（右）操作数，蓝色扇面指向左操作数。

这只是一个起点。我们可以
* 可视化复合表达式
* 对任意合法形状与尺寸的参数建模（在实用极限内）
* 通过预设初值、自定义表达式或加载数据指定数值
* 动画演示多种算法
* 可视化分块与融合
* 或多或少自定义可视化本身的一切

## 直觉速览

* 旋转、缩放并检查数值（见上方 **交互**）
* 动画演示
  成对点积、
  矩阵-向量积、
  向量-矩阵积、
  外积累加
  （更快、
  更慢、
  停止）
* 用随机值初始化（回到 rows 与 columns）
* 一些常见形状：
  宽到窄（如 q/k/v 投影）、
  窄到宽（如低秩分解）、
  大 batch、
  小 batch
  （回到立方体）
* 更大、更小
* 沿 i 切分矩阵乘、
  沿 j、
  沿 k
  （取消切分）
* 用 local 敏感度可视化数值——尺寸与颜色按矩阵分别归一化，
  而不是跨整个可视化统一
  （回到 global 敏感度）
* 隐藏引导线、隐藏全部装饰（回到默认装饰）

几个稍进阶的示例，用本指南其余部分介绍的菜单选项分几步即可构建
（上面的链接对这些示例同样可用，形状重置除外）：
* 类似注意力的双重矩阵乘：out = (attn = Q @ K) @ V
* 带输入/输出投影的注意力：
  out = (attn = (Q = input @ wQ) @ (K = wK @ input_t)) @ (V = input @ wV) @ wO
* 类似 MLP 的左结合链：
  out = (x1 = (x0 = batch @ w0) @ w1) @ w2
* 权重带低秩分解的 MLP：
  out = (x1 = (x0 = batch @ (w0 = w0_L @ w0_R)) @ (w1 = w1_L @ w1_R)) @ (w2 = w2_L @ w2_R)

# mm 菜单

配置通过右上角的 **mm** 菜单交互式指定。
所有选项都直接映射为 URL 中编码的属性。

* **顶层**选项
  配置全局属性，主要是矩阵乘表达式本身的结构
* **left** 与 **right** 子菜单
  配置顶层矩阵乘的左、右操作数，包括初始化与形状
  * 若某个操作数本身是子表达式，对应子菜单会有自己的 left/right 子菜单
* **animation** 子菜单
  控制矩阵乘计算的动画方式
* **blocking** 子菜单
  配置表达式如何分块
* **layout** 子菜单
  控制表达式在 3D 空间中的朝向与间距
* **deco** 子菜单
  配置图例、朝向引导等装饰，以及数值显示选项
* **colors and sizes** 子菜单
  配置数值映射的颜色与亮度细节
* **diag** 子菜单
  包含统计与数据，如当前 URL、JSON 配置对象等

# 顶层

## expr

可直接编辑 **expr** 来指定所可视化矩阵乘的结构。
（也可以通过 **left**、**right** 子菜单交互式构建结构——这些子菜单无论如何都会配置矩阵乘各组成部分的属性。）

表达式形式为 `left @ right` 或 `result = left @ right`，其中
* `left` 与 `right` 可以是子表达式
* `result` 命名被可视化的结果矩阵（未提供时使用表达式本身）
* 括号用于分组右结合子表达式与子表达式赋值

编辑 **expr** 时会尽力保留现有设置——尤其是复用的名字。

以下示例展示仅编辑当前可视化的 **expr**（不做其它修改）的效果：
* 类似注意力的双重矩阵乘：out = (attn = Q @ K) @ V
* 左结合链：A @ B @ C @ D
  * 带命名结果：X = (ABC = (AB = A @ B) @ C) @ D
* 右结合链：X = A @ (B @ (C @ D))
  * 带命名结果：X = A @ (BCD = B @ (CD = C @ D))
* 左右子表达式：(L = LL @ LR) @ (R = RL @ RR)
  * 子又生子：(L = (LL = LLL @ LLR) @ (LR = LRL @ LRR)) @ (R = (RL = RLL @ RLR) @ (RR = (RRL @ RRR)))
  * 注意：**layout** 子菜单提供多种选项，
    可以为这类深度嵌套的饱和表达式可视化"留出空气"——
    例如在子表达式与父级之间增加间距、
    使用分散
    或稠密的子表达式布局。
    （回到默认）
  * 另外，对于同时包含极小和极大值的这类表达式，把
    敏感度设为 local（在 **visualization** 子菜单中）
    可能很有用。它会把元素颜色与尺寸按每个矩阵分别归一化，
    而不是跨整个表达式统一。
    （回到 global）

## name

为正在计算的矩阵乘的结果矩阵命名。可直接编辑，
和/或与 **expr** 同步。

## epilog

指定顶层矩阵乘计算完成后作用于结果矩阵的函数。

（子矩阵乘有自己的 epilog 选择，在 **left** 与 **right** 子菜单中。）

* none：无 epilog，结果值不修改
* relu：对结果值应用 relu
* gelu：对结果值应用 [gelu](https://arxiv.org/pdf/1606.08415.pdf)
* sigmoid：对结果值应用 [sigmoid](https://paperswithcode.com/method/sigmoid-activation)
* silu：对结果值应用 [silu](https://arxiv.org/pdf/1702.03118v3.pdf)
* tanh：对结果值应用 tanh
* layernorm：对结果值应用整矩阵 layernorm
* softmax：按行对数值做 softmax
* softmax(x/sqrt(k))：数值先按矩阵乘深度的平方根缩放，
  再按行做 softmax（如缩放点积注意力）
* softmax(tril(x/sqrt(k)))：数值先按深度的平方根缩放，
  再屏蔽上三角，然后按行做 softmax（因果 SDPA）

# Left 与 Right

left 与 right 子菜单配置所可视化矩阵乘的左、右操作数。

菜单选项取决于该操作数本身是否为矩阵乘，如下所述：
子表达式可任意深度嵌套，left/right 子菜单也会相应嵌套。

## name

为该操作数命名。可直接编辑，和/或与 **expr** 同步。

## matmul

该复选框指定操作数本身是矩阵乘还是普通矩阵。
菜单中后续选项取决于该项取值。

## *Left/Right 矩阵选项（matmul 未勾选）*

## h, w

矩阵高与宽。左操作数的宽度与右操作数的高度会自动同步。

## init

指定矩阵数值的初始化方式。提供多种初值函数，
也可以从 CSV 文件加载外部数据。

#### 基于位置

* **rows**：每行元素初始化为相同值，值在 **min**、**max** 指定的范围内均匀分布。
  把左操作数 init 设为 rows
* **cols**：每列元素初始化为相同值，值在 **min**、**max** 指定的范围内均匀分布。
  把右操作数 init 设为 cols
* **row major**：元素按行主序从左上到右下初始化，值在 **min**、**max** 指定的范围内均匀分布。
  把左操作数 init 设为 row major
* **col major**：元素按列主序从左上到右下初始化，值在 **min**、**max** 指定的范围内均匀分布。
  把右操作数 init 设为 col major

#### 随机

* **pt linear**：元素从与形状相关的均匀分布中抽取，见
  [此处](https://pytorch.org/docs/stable/generated/torch.nn.Linear.html)。
  把左右操作数 init 都设为 pt linear
* **uniform**：元素从 **min**、**max** 指定的均匀分布中抽取。
  把左右操作数 init 都设为 uniform
* **gaussian**：元素从 **min**、**max** 指定的高斯分布中抽取。
  把左右操作数 init 都设为 gaussian

#### 代数

* **tril mask**：下三角元素初始化为 1，其余为 0。
  把左操作数 init 设为 tril mask
* **triu mask**：上三角元素初始化为 1，其余为 0。
  把左操作数 init 设为 triu mask
* **eye**：对角线元素初始化为 1，其余为 0。
  把左操作数 init 设为 eye
* **diff**：对角线元素初始化为 1；紧邻对角线下方的元素初始化为 -1，
  其余为 0。把左操作数 init 设为 diff

#### 自定义

* **url**：显示 **url** 字段，用于指定指向 CSV 初始化数据的 URL。
  加载的数据按行消费，当矩阵形状超出可用数据时按行、按列循环复用。
  把左右操作数 init 都设为 sample loaded weights
* **expr**：显示 **expr** 字段，用于指定 Javascript 初始化表达式。
  可用变量为 `i`（行下标）、`j`（列下标）、`h`（矩阵高）与 `w`（矩阵宽）。

## dropout

为行/列与随机初始化指定 0（0%）到 1（100%）之间的稀疏度。
* 把左右操作数 dropout 设为 0.5（若当前 init 选择适用）

## *Left/Right 矩阵乘选项（matmul 已勾选）*

当 **left** 和/或 **right** 子菜单中的 **matmul** 选项被勾选时，矩阵选项
（h/w、init 等）被移除，改为矩阵乘选项：left/right 子子菜单、epilog、animation
以及（取决于全局选项）layout。

# 动画

多种矩阵乘算法都可动画演示。在复合表达式中，
动画按依赖顺序从叶到根推进，相互独立的子表达式并行推进。

算法也会在分块内并行化。

几何条件允许时，跨矩阵乘的融合会自动发生——详见下方 **fuse** 选项。

## alg

指定要动画演示的矩阵乘算法。

复合表达式动画演示时，每个子矩阵乘通过 **animation** 子菜单选择自己的
动画算法——或选择继承父级算法。

当矩阵乘指定算法 `none` 时，以该矩阵乘为根的表达式树不做动画：
顶层选择 `none` 会全局禁用动画，
而子节点中的 `none` 只禁用该子表达式的动画。

* none：该矩阵乘及其子节点均无动画
* dotprod (row major)：结果矩阵元素按**行主序**通过**成对点积**计算
* dotprod (col major)：结果矩阵元素按**列主序**通过**成对点积**计算
* axpy：结果矩阵的列通过**向量-标量积**的深度累加计算
* vmprod：结果矩阵的行通过左操作数各行上的**向量-矩阵积**计算
* mvprod：结果矩阵的列通过右操作数各列上的**矩阵-向量积**计算
* vvprod：结果矩阵通过**向量-向量外积**的深度累加计算
* **inherit**（仅子矩阵乘）：继承父级算法。这是新建子矩阵乘的
  默认设置

## speed

指定动画速度。该设置的数值并未精确校准：1 非常慢，100
基本就是浏览器动画帧的上限速度（复杂可视化会在远低于 100 时
达到实际速度上限）。

注意动画速度*并不*按工作量比例校准：无论算法或参数形状如何，
每帧只推进一步。

选择上方任一算法，调快或调慢运行。

## pause

勾选时暂停动画。

## step

让暂停中的动画前进一步。配合 **interior spotlight**（见 deco 菜单）
可用于检查中间数值。

## fuse

在复合矩阵乘表达式中，相邻平面算法（向量-矩阵、
矩阵-向量、
向量-向量）的特定组合
在生成平行平面时可以**融合**。

平行平面在视觉上表示共享的*扫描轴*，数据依赖可沿该轴
在相邻矩阵乘之间切分，
即共面算法可以融合并并行。

（无论是否融合，分区都可以在 **blocking** 子菜单中显式可视化。）

### 可融合对

以下两矩阵乘表达式形状与算法组合会生成平行平面：

#### 左结合：`A @ B @ C`

| `A @ B`（左子） | `_ @ C`（顶层） | |
| - | - | - |
| vector-matrix product（沿 **i** 融合） | vector-matrix product（沿 **i** 融合） | Show |
| matrix-vector product（沿 **k** 融合） | vector-vector product（沿 **j** 融合） | Show |

#### 右结合：`A @ (B @ C)`

| `B @ C`（右子） | `A @ _`（顶层） | |
| - | - | - |
| vector-matrix product（沿 **i** 融合） | vector-vector product（沿 **j** 融合） | Show |
| matrix-vector product（沿 **k** 融合） | matrix-vector product（沿 **k** 融合） | Show |

### 融合链

可以把多个具有共同平行平面的对拼接起来，形成扩展融合。一些示例：

* **`A @ B @ C @ ...`**：推广上述第一种左结合模式，
任意长度的左结合链都可以沿 **i**（**向量-矩阵**积）融合。
这里贯穿复合表达式的平面对应例如单个 batch 项
在 [MLP](https://pytorch.org/docs/stable/generated/torch.nn.Linear.html) 中的计算路径。
这种层流几何正是[数据并行](https://pytorch.org/docs/stable/generated/torch.nn.DataParallel.html)
（把 batch 切分到多个节点）的基础：
  * 示例：`X = A @ B @ C @ D @ E`
* **`A @ (B @ (C @ (...)))`**：类似地，上述第二种右结合模式可以推广
为任意长度的右结合链沿 **k**（**矩阵-向量**积）融合。
  * 示例：`X = A @ (B @ (C @ (D @ E)))`
* **`(A @ B) @ (C @ D)`**：二元表达式可以让左子表达式沿 **k**
  （**矩阵-向量**积）、右子表达式沿 **i**（**向量-矩阵**积）计算，并在
  根处沿 **j**（**向量-向量**积）连接，从而融合。
  * 示例：`X = (A @ B) @ (C @ D)`
* **`(A @ (...)) @ ((...) @ Z)`**：更一般地，左侧为任意长度*右*结合链、
  右侧为任意长度*左*结合链的二元表达式，可以按前面示例的方式
  融合链式子表达式，再在根处沿 **j**（**向量-向量**积）连接，
  融合为一个整体。
  * 示例：`X = (A @ (B @ C)) @ ((D @ E) @ F)`

### *sync 与 async*

**fuse** 的选项为 `none`（不融合）、`sync` 与 `async`。`sync` 与 `async` 的差异
很微妙，只有大型复合矩阵乘动画时才能观察到。当 **fuse** 为 `sync` 时，
所有参与者能同时开始计算（即不在等待子计算完成）时才融合动画；
而 `async` 动画即使参与者开始时间不同，只要依赖顺序允许，
也会融合。

对大多数表达式，`sync` 与 `async` 表现相同。

## hide inputs

动画时隐藏输入，可以更容易地观察
矩阵乘立方体内部渲染的中间结果可视化，
尤其是把 **deco** 菜单选项调到最少装饰并启用 interior spotlight 时
（后者会显示中间可视化的数值——详见 **deco**）。

## spin

旋转可视化有助于建立对所演示运算的几何直觉。
* 顺时针旋转、
  逆时针旋转
* 更快、
  更慢、
  停止

# 分块

简单与复合表达式都可以在 3 个维度上分块。
分区是*全局*的：切割平面贯穿子表达式，
表示整个复合表达式的并行化。

分区传播规则很直接（但注意 `k` 的微妙之处）：
* 沿 `i` 轴的分区沿左操作数的连续链延伸
* 沿 `j` 轴的分区沿右操作数的连续链延伸
* 沿 `k` 轴的分区对左子变成沿 `j` 轴的分区，
  对右子变成沿 `i` 轴的分区（之后适用上面的 `i`/`j` 规则）

所有维度的分区可以自由混合。

每个维度的分区对应不同的并行化方式，
具有独特的几何特征。
动画会在当前配置的分区内并行化。

各块大小相等；块数不能整除时最后一块较短。

## i blocks

把表达式沿 **i** 轴分成指定数量的块。

**i** 是根矩阵乘及其左后代链的高度维（行）。切分它会在根矩阵乘的
高度范围内把表达式切成水平薄片：即根矩阵乘及其左后代被分区，
而以右后代为根的矩阵乘不受影响。

沿 **i** 分成 4 块的示例
（回到 1）：
* X = A @ B（动画：
  dotprod、
  mvprod、
  vmprod、
  vvprod -
  更快、更慢、停止）
* X = A @ B @ C（动画：
  dotprod、
  mvprod、
  vmprod、
  vvprod、
  fused vmprod、
  fused left mvprod/parent vvprod -
  更快、更慢、停止）
* X = A @ (B @ C)（动画：
  dotprod、
  mvprod、
  vmprod、
  vvprod、
  fused mvprod、
  fused right vmprod/parent vvprod -
  更快、更慢、停止）
* X = (A @ B) @ (C @ D)（动画：
  dotprod、

* 父级中沿 **k** 的分区变成右子中沿 **i** 的分区

# 布局

layout 子菜单控制矩阵乘及其操作数在 3D 空间中的排列。
配置选项分为两类：**间距**与**朝向**。

**间距**选项以多种方式影响元素之间的距离。
间距选项有 **gap**、**scatter**、**molecule** 与 **blast**。

对许多可视化，默认间距设置就足够了；但对深度
嵌套的表达式——尤其是左右子表达式都很饱和的——
微调这些参数可以澄清可视化并带来新洞察。

**朝向**选项控制矩阵乘的操作数与结果在立方体上的放置。
**polarity**、**left placement**、**right placement**
与 **result placement** 控制根矩阵乘各部分的放置，而 **scheme**
控制子表达式的放置如何从父级的放置演化而来。

同样，默认设置通常就够用，但在不同 scheme 之间切换
有时对建立直觉非常有用。

### *间距选项*

## gap

矩阵乘各组成部分（左操作数、右操作数、结果）沿共享边缘的
间隙。单位距离大致相当于一行或一列。
* 增大 gap、减小 gap

## scatter

定义子*矩阵乘*与其父级之间的固定距离。（简单子矩阵不受 scatter 影响。）

与 **molecule**、**blast** 共同计算可视化中使用的实际距离；
见下文。
* 示例：使用 X = A @ B @ (C @ D) @ (E @ F @ (G @ H))（或当前可视化）
增大 scatter、减小 scatter

## molecule

"大分子"是过大而无法紧贴父级的子表达式——即
开始应用 **scatter** 的规模阈值（子表达式规模 = 其包含的矩阵乘个数）。
* 示例：组合使用
  大 molecule 与 scatter，紧凑地可视化一个深度完全饱和的表达式
  且不产生空间碰撞。

## blast

基于子表达式规模（矩阵乘个数）作用于 **scatter** 的指数缩放项。

blast 为零时 scatter 保持不变；正值使更大的子表达式
离父级更远——例如 blast 为 1 时 scatter 乘以子表达式规模。
负 blast 使更小的子表达式离父级更远。

正 blast 对可视化深度饱和的树很有用，
效果类似于 2D 可视化中树的较低层级
聚得更紧密。

* 示例：上述 **molecule** 示例的另一种布局，
  使用更小的 scatter、更小的 molecule 和正的 **blast** 值。

负 blast 对饱和的树状表达式效果不太好，但对
主要或完全线性的表达式配合圆形几何布局
（例如下文 **wheel**）很有用。这类情况下，任意非零 blast 会把圆变成
螺线：正 blast 向外螺旋到根矩阵乘，负 blast 向内螺旋。

### *朝向选项*

在介绍选项本身之前，先补充一些背景：

#### 排列的约束

把一个矩阵乘（左操作数、右操作数、结果）安排在
立方体的 3 个面上，受以下约束（注意：这里的"立方体"
指"长方体"）：

* 邻接约束：
  * 左右操作数必须共享一条公共边，由此确定 `i, k, j` 中的 `k` 轴
  * 结果矩阵必须与左操作数共享一条边，由此确定 `i` 轴
  * 结果矩阵必须与右操作数共享一条边，由此确定 `j` 轴
* 朝向约束：
  * 左操作数的行必须**平行**于 `k` 边
  * 右操作数的行必须**垂直**于 `k` 边
  * 结果矩阵的行必须与左操作数的行共面，
    从而其列与右操作数的列共面

视觉上这意味着我们总是覆盖立方体的 3 个面，围绕一个
共享角连续分布，且各面的行/列朝向服从上述约束。

为便于熟悉，我们再加一条约束：左操作数总是
占据根矩阵乘立方体的竖直面。
因此，右操作数总是占据水平面，
结果矩阵也占据竖直面。

这些约束仍留有调整空间。合法排列的空间
可以用四个正交的二元属性参数化：
**polarity**（positive/negative）、**left placement**（left/right）、
**right placement**（top/bottom）与 **result placement**（front/back）。
各项细节见下文。

#### 子表达式

上述约束与参数足以可视化单个矩阵乘
（左右操作数为矩阵）。
要可视化复合表达式（操作数本身可以是矩阵乘），
我们需要先把子矩阵乘立方体拼接到父级上，然后
决定子立方体的参数化方式。

子级拼接有一个自然约束：
父立方体上表示子操作数的面必须同时是子立方体的*结果*
面。
在此约束下，每个子立方体可以自由选择合法的布局参数化。
定义"根据父级参数化生成子级参数化"的规则
省去了为复合表达式中每个矩阵乘手工参数化的工作——
这些规则就是 *scheme*。

## scheme

*scheme* 是根据父级布局选择子级布局的规则。
在复合表达式的矩阵乘上迭代时，不同 scheme 会产生
明显不同的可视化。

从本指南其它部分选一个复合矩阵乘，然后点击下方链接
尝试不同 scheme。请记住最终可视化在很大程度上取决于
初始 placement 的选择——可用那些选项中的链接尝试不同
组合。

* **blocks：默认 scheme**，把
表达式展开为凸凹交替的立方体。这类可视化通常
易于理解，且对相当大而饱和的表达式也抗碰撞。
本指南所有可视化默认使用 **blocks** scheme。
  * 使用 block scheme 与默认 placements 的 A @ B @ C @ D
  （动画演示 matrix-vector product、停止）
* **zigzag**：与 **blocks** scheme 类似，
使用交替，但不变换凸凹。这可以简化
某些可视化的流向，代价是遮挡更多：
  * 使用 zigzag scheme 与 right placement at bottom 的 A @ B @ C @ D
  （动画演示 matrix-vector product、停止）
* **wheel**：简单地把每个子级旋转 90
度，对简单（子）表达式可以产生直观的圆形可视化，
但容易产生空间碰撞（可用间距修复）。
  * 使用 wheel scheme 与 right placement at bottom 的 A @ B @ C @ D
  （动画演示 matrix-vector product、停止）
* custom：选择此项时
完全不应用生成规则，而是在所有子子菜单中
开放布局参数。

*（注意：一般情况下空间碰撞不可避免，
尽管不同 scheme 的碰撞倾向以及导致碰撞的表达式
形状不同：特别是默认的 **blocks** scheme 通常
不会为表达式产生碰撞，除非表达式既饱和又嵌套
超过 3 代。无论如何，发生碰撞时都可以用上面的间距选项
解决。）*

## polarity

控制左右操作数相对结果矩阵的朝向：
当操作数的法线指向其结果中对应共面部分（左对应行、右对应列）
的*增大*方向时为正 polarity，
指向*减小*方向时为负 polarity。

例如，当左右操作数按标准立方体放置（左操作数
在左、右操作数在上）时，负 polarity 对应操作数
面"朝外"，从立方体外部按惯常方式从左到右、从上到下
读取数值。

该朝向通过*行引导线*中的角三角形在视觉上标示，
位于矩阵的 (0, 0) 角。

## left placement

控制左操作数放在立方体的左面还是右面。

## right placement

控制右操作数放在立方体的上面还是下面。

## result placement

控制结果矩阵放在立方体的前面还是后面。

# 颜色与尺寸

## sensitivity

被可视化矩阵元素的尺寸、亮度与颜色取决于其绝对值
落在某个范围内的位置。
sensitivity 控制每个值的比较范围如何构造。

global 敏感度对所有值使用单一范围：从零到
可视化中的全局最大绝对值。这会产生数值尺寸、
亮度与颜色视觉上一致的画面，但在高方差数据中
小值可能显得很淡。

local 敏感度对每个矩阵使用独立的比较范围：
从零到该矩阵中的最大值。
这会增加高方差可视化传达的视觉信息量，代价是
全局一致性。

superlocal 更进一步，不用零而用
局部矩阵中的最小绝对值作为下限。这可以增强
数值都落在远离零的狭窄区间内的矩阵可视化。

semilocal 使用从零到全局与局部绝对最大值
几何平均的范围。

## min size

最小渲染尺寸。（恰好等于零的值不渲染。）
* 增大 min size、减小 min size

## min light

最小渲染亮度。
* 增大 min light、减小 min light

## max light

最大渲染亮度。
（注意数值使用 HSL 颜色模型渲染，亮度接近最大值 1 时颜色趋白。）
* 增大 max light、减小 max light

## elem scale

应用于所有元素的恒定缩放因子。
* 增大 elem scale、减小 elem scale

## zero hue

零值的色相。正值的色相更高，负值更低。（注意 HSL 模型中色相会环绕。）
* 增大 zero hue、减小 zero hue

## hue gap

从零色相到数值色相开始处的距离。更大的 hue gap 会增大正负值
之间的颜色差异。
* 增大 hue gap、减小 hue gap

## hue spread

色相随数值幅度变化的速率。
* hue spread 为零时，所有正值与所有负值
  分别使用同一色相
* 较小的 spread 会基于幅度引入小幅色相变化，同时
  保持正负值可区分
* 较大的 spread 会使色相完全随幅度变化，
  极端情况（spread 为 1）下正负幅度变化都会遍历整个频谱，
  但方向不同
* 增大 hue spread、减小 hue spread
